# Меню Лакея: `(つ✧ω✧)つ`, «В гости», «Вписаться» (04.11.2026)

Реализация ТЗ `docs/lakey-tz.md`. Логика сценариев вынесена в **новые** файлы,
старый код тронут минимально (см. «Изменённые файлы»).

## Что работает

- **Reply Keyboard** `(つ✧ω✧)つ` — постоянная (`is_persistent`), прикладывается к ответу `/start`
  (и для новых, и для вернувшихся пользователей). Нажатие открывает «🪁Меню:».
- **Главное меню** (inline): `Вписаться · В гости` / `Написать · Список коммун` / `Поддержка`.
- **Написать** и **Список коммун** — экраны с кнопкой `Назад`, правятся на месте. Оба — **Rich Message**
  и берутся из тех же источников, что `/help`, `/start` и `/list`, без копий текста:
  «Написать» = `presentation.texts.DM_HELP` (`HOW_TO_WRITE` + `REPLY_HINT` + `DM_COMMANDS_BLOCK` + `FOOTER`),
  «Список коммун» = `build_full_list_text()` (`AdminService.render_full_list_text`: настоящий `<h2>`, секции, `aka`, 🤖Сетевики).
  Правка констант в `texts.py` или оформления списка в `AdminService` сразу меняет и меню.
- Все экраны меню (главное меню, «Город?», «Коммуна?», «Когда?», дни, текст) — тоже Rich: открываются через
  `send_rich`, переключаются через `editMessageText(rich_message=...)`. Rich → Rich, без смены типа сообщения.
- **В гости**: Город → Коммуна → Когда → Текст → заявка в коммуну.
- **Вписаться**: Город → Коммуна → Когда → На сколько дней → Текст → заявка в коммуну.
- `Назад` везде возвращает на предыдущий шаг; с «Город?» — в главное меню.
- Итог в коммуне:
  ```
  @user хочет прийти сегодня в гости          (первая строка жирная, как шапки остальных релеев)
  ↳ текст
  @user хочет вписаться сегодня на 4 дня
  ↳ текст
  ```
  Склонение: 1 день / 2–4 дня / 5+ дней (11–14 → дней).
- Реакция только ✍ (ставит общий pipeline), 🌟 нет — это была ошибка ТЗ. Дальше переписка идёт как после обычного `Коммуна! привет`.
- Заявка идёт через общий `DeliveryPipeline`: Mongo-claims от дублей, mapping для reply-цепочек
  (коммуна может ответить на сообщение бота, и ответ вернётся в ЛС), статистика.
- `/anon` на заявки не действует: они всегда от @username. **Весь диалог после заявки тоже открытый**: на связке (`threads.open_identity`) ставится флаг, он наследуется по цепочке ответов в обе стороны (`ReplyService`, `DeliveryPlan.open_identity`). Анонимность работает только для обычных сообщений `Коммуна! текст` и их reply-цепочек.

## Решения, принятые по умолчанию (легко поменять)

| Вопрос из ТЗ | Решение | Где менять |

| Что после отправки | Сценарий закрывается, меню не открывается заново (реакция — подтверждение) | `deliver_request` в `handlers/menu.py` |

| «Сколько дней» | Целое 1…60 | `MAX_DAYS` |
| Длина послания | до 2000 символов | `MAX_TEXT_LEN` |

## Детали поведения

- **Rich можно редактировать.** В прошлой версии патча считалось, что нельзя, поэтому экраны были plain HTML
  с копией текста и своим сборщиком списка. `editMessageText` принимает `rich_message` (aiogram 3.31). При правке
  `parse_mode` и `link_preview_options` явно сброшены в `None`, иначе aiogram добавил бы дефолтный
  `parse_mode=HTML` бота прямо в запрос рядом с `rich_message`.
- Кнопки на меню, отправленном прошлой версией патча (plain), после обновления ответят «Меню устарело —
  нажми (つ✧ω✧)つ»: тип сообщения сменить правкой нельзя. Новое меню откроется как Rich.
- Состояние шагов — в Mongo, коллекция `menu_flows` (один документ на пользователя), **TTL 20 минут**
  без активности; индексы создаются в `db.connect()`.
- Кнопки со старого экрана (не последнее сообщение сценария) отвечают «Меню устарело».
- Если посреди сценария пользователь пишет обычное `Башня! привет`, это уходит как обычное сообщение,
  а сценарий закрывается. Reply на сообщения бота сценарий не перехватывает.
- Любая команда, кроме `/anon` и `/deanon`, отменяет сценарий (`/list` и `/help` обрабатываются
  раньше и сценарий не трогают).
- Вход в меню снимает незавершённый черновик `/communesite`, чтобы текст не ушёл в отзыв.
- Ошибка доставки: сценарий остаётся на шаге «текст», можно отправить ещё раз.
