# Lackey × Communars — патч A: SiteFeedback

Дата: 2026-10-21. База: **Lackey Stage 5** (`Lackey_stage5_20261021.zip`).

## Граница и порядок релизов

- A (этот архив): **только Telegram-бот и его MongoDB**, ни одного изменения PHP-сайта.
- C (следующий этап): авторизация и серверный API подсайта, связка с общей очередью.
- Затем **сквозное тестирование A+C на стенде**.
- B (объявление всем коммунам): **строго после успешных тестов C и явного подтверждения отправки**. В A нет массовой рассылки, она не планируется автоматически.

## Команды и пользовательский сценарий

- `/communesite` и `/communeSite`: меню в личных сообщениях с кнопками «Оставить отзыв», «Предложить новую страницу», «Мои предложения».
- `/start communesite`: вход через будущий deep-link (для последующего патча B).
- Отзыв: категория страницы → (для URL с `{slug}` необязательно указать slug) → тип «улучшение/ошибка/замечание» → текст 10–2000 символов → предпросмотр и отправка.
- Предложение новой страницы: название 4–100 символов → описание 20–2000 символов → подтверждение.
- `/cancel`: отмена активного черновика. Невыполненные черновики живут в Mongo не дольше 7 дней.
- «Мои предложения»: список по 5, просмотр карточки, история изменений статуса.
- Авторство Telegram ID из Bot API, **никогда из введенного username**. `@username` индексируется как наблюдавшийся атрибут, возможны совпадения старых username с другими людьми.
- `/anon` касается **только DM-пересылки**. Отзывы `moderators_only`: автор виден `ADMIN_ID` вместе с ID и username. Пользователь видит предупреждение перед подтверждением.

## Администратор

В ЛС ботa, строго `ADMIN_ID`:

- `/sitefeedback`: кнопки всех статусов и очереди.
- `/sitefeedback new`, `/sitefeedback in_review`, `/sitefeedback accepted`, `/sitefeedback rejected`, `/sitefeedback implemented`.
- `/sitefeedback @username`: поиск по текущему/ранее замеченному username. Если найдено несколько Telegram ID, бот предложит выбрать ID явно.
- `/sitefeedback 123456789`: все обращения выбранного Telegram ID с пагинацией.
- `/sitefeedback <24-символьный ObjectId>`: конкретное обращение.
- Кнопки модерации: `new` → `in_review`/`accepted`/`rejected`, `accepted` → `implemented`/`in_review`, `rejected` → `in_review`; историю нельзя потерять при конкурентном обновлении (атомарная смена статуса и `$push` события в одном документе).
- `/sfnote <24-символьный ObjectId> текст`: комментарий от имени администратора с отправкой автору.
- Автору приходят уведомления при смене статуса и при комментариях. Если Telegram недоступен/пользователь заблокировал бота, решение в БД всё равно остаётся.

## MongoDB: новые коллекции

- `site_feedback_pages`: реестр страниц на базе реальных PHP-маршрутов. Начальные маршруты: `home`, `commune_profile`, `commune_members`, `commune_join`, `events`, `event_profile`, `event_create`, `login`. Админские `admin` и `moderation` также хранятся, но не видны пользователям.
- `site_feedback_items`: обращения; индекс `submission_key` уникален (защищает от повторной отправки по одному черновику); индексы автор + дата, статус + дата, страница + дата.
- `site_feedback_users`: текущий username и известная история ников; первичный ключ — Telegram ID. Зависимость от членства в коммуне не выдумывается.
- `site_feedback_drafts`: состояния диалога, TTL 7 дней после обновления.
- История действий модератора **атомарно встроена в `site_feedback_items.history`**, не в отдельную коллекцию: это сохраняет событие в одной операции со сменой статуса и не требует транзакций MongoDB для standalone-инсталляций.
- `delivery_claims`, `threads`, `dm_sessions`, чаты и статистика не менялись.

## Безопасность

- Пользователь может смотреть только свои обращения. Модерация только ADMIN_ID, только в ЛС.
- Чужие callback ID не дают доступа к содержимому.
- Все видимые пользователю строки проходят HTML-экранирование; slug валидируется.
- Уникальный `submission_key` генерируется сервером, хранится с черновиком. При повторном нажатии/потере Telegram-ответа запись не дублируется.
- `site_feedback_pages` допускает дальнейшее наполнение новым web-manifest без новых Python-констант в runtime; manifest и его авторизация относятся к C.
- Админка PHP сейчас демонстрационная, в ней **нет** доступа к персональным отзывам и ID.
- В этом MVP нет автоматических публичных отзывов, скриншотов, голосований, опросов или заявок на вступление.

## Установка

1. Остановить бота и создать резервную копию файлов. MongoDB оставить без изменений, сделать свой backup по штатной процедуре.
2. Распаковать ZIP поверх **Stage 5**; не перезаписывать свои `.env` и `MONGODB_URI`.
3. В `.env` можно добавить `SITE_FEEDBACK_BASE_URL=https://communars.itcheckup.pro` (уже есть безопасный default).
4. `pip install -r requirements.txt`; затем `python -m unittest discover -s tests -v` и `python -m compileall -q .`.
5. `python bot.py`: при `db.connect()` создаст только новые индексы и заполнит реестр, не сбрасывая старые коллекции.
6. В ЛС проверить `/communesite`, отзыв «Главная», предложение страницы, «Мои предложения», `/cancel`; владельцу — `/sitefeedback`, `@username`, смену статуса, `/sfnote`, уведомление автора.
7. Убедиться, что старые `НазваниеКоммуны!`, reply и пересылки Stage 5 работают.

**Внимание:** Telegram API и настоящую MongoDB внутри среды разработки не подключали. Автоматические тесты выполняются с подменой внешних зависимостей. Обязательно проверить на тестовом боте до использования с участниками коммун.

## Диагностика Mongo (mongosh, необязательно)

```javascript
use tgbot
show collections
db.site_feedback_pages.countDocuments({visible:true,access:'public'})
db.site_feedback_items.getIndexes()
db.site_feedback_users.getIndexes()
db.site_feedback_items.find({}, {status:1,kind:1,'author.telegram_user_id':1}).limit(5)
```

DB_NAME может отличаться от `tgbot`.

## Откат

Остановить бота, восстановить ZIP Stage 5 поверх исходников, сохранить `.env`. Новые `site_feedback_*` коллекции можно оставить нетронутыми — старый код их не использует. Удалять их при откате **не требуется**.
