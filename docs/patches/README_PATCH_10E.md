# Patch 10E — hotfix DM/reply после выноса ЛС handlers

## Что исправлено

После Patch 10D `dm.router` подключался раньше `main.router`. Из-за этого обычные ЛС-хэндлеры перехватывали сообщения, которые были reply на доставленные ботом сообщения, и они не доходили до `ReplyService`.

В этом патче DM-хэндлеры теперь обрабатывают только обычные ЛС-сообщения и ЛС-медиа, которые **не являются реальным reply**. Реальные reply-сообщения пропускаются дальше и снова обрабатываются reply-слоем в `main.router`.

## Изменённые файлы

- `adapters/telegram/handlers/dm.py`
- `README.md`
- `docs/patches/README_PATCH_10E.md`

## Что не трогали

- `ReplyService`
- `RelayService`
- `ModerationService`
- `CaptchaService`
- Mongo schema
- `bot.py`
- `build.sh`

## Как проверить

1. В ЛС ответить reply на сообщение, доставленное ботом из коммуны.
2. Проверить, что reply уходит обратно в исходную коммуну.
3. В ЛС отправить обычное сообщение формата `НазваниеКоммуны, текст`.
4. В ЛС отправить медиа формата `НазваниеКоммуны,` + фото/документ.
5. В группе проверить обычный relay и reply на доставленное сообщение.
6. Запустить `python -m compileall .` и `bash build.sh`.
