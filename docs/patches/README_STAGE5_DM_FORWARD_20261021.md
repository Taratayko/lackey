# Lackey Stage 5 — пересылка из ЛС через reply (2026-10-21)

Основа: проверенная пользователем `Lackey_stage4_20261020.zip`. Это небольшой патч поверх Stage 4, полный проект включён. MongoDB-миграции не нужны, прежняя база/`.env` сохраняются.

## Причина

В `adapters/telegram/handlers/forward_reply.py` была явная ветка:

```python
if intent is None or msg.chat.type == "private":
    return False
```

Она исключала личные диалоги **до** вызова `RelayService`, независимо от корректности адреса. Поэтому в ЛС команда `B!`, отправленная как ответ на сообщение, не приводила к пересылке. В ответах на бот-сообщение могла попадать в обычную reply-цепочку.

## Изменения

1. `adapters/telegram/handlers/forward_reply.py`: обработчик теперь принимает команды `B!` и `B! комментарий` как из коммун, так и из ЛС. Для ЛС вызывает `relay_dm`, для групп — прежний `relay_group`. Явное сообщение об ошибке для запрещённого направления из ЛС.
2. `application/services/relay.py`: ЛС-пересылка использует приватный формат заголовка, учитывает `/anon`, не обходит правила `dm_destination_allowed`, в том числе при `redirect_to`. При `/anon` устанавливается режим копирования исходного сообщения без Telegram-атрибуции пересылки.
3. `application/services/delivery.py`: общая доставка поддерживает дополнительную часть `copy` через `copyMessage`, с теми же mapping/claims, что и обычная пересылка.
4. `ports/channel.py`, `adapters/telegram/message_transfer.py`, `adapters/telegram/sender.py`: новый порт копирования и Telegram-реализация. Forward/copy вынесены в отдельный файл, все Python-файлы укладываются в ограничение 400 строк.
5. `tests/test_stage5_dm_forward.py`: новые тесты реального handler/service, reply из B обратно в ЛС, `/anon`, запретов, дедупликации и возвращаемого `MessageId` метода `copyMessage`.

## Как проверить в Telegram

1. Запустить бота и открыть **личный чат с ботом**.
2. Переслать туда любое доступное текстовое сообщение или фото из другого чата. Это создаст сообщение в личном диалоге с ботом.
3. Ответить **именно на это сообщение** текстом `B!`, где `B` — точное имя зарегистрированной коммуны. Можно отправить `B! небольшой комментарий`.
4. В `B` должны появиться заголовок «из ЛС» и оригинальное сообщение; оба должны быть видны, reply на каждое сообщение должен возвращаться в личный чат **ответом на исходное пересланное сообщение**.
5. Повторить с сообщением, **которое сам бот написал в ЛС**: ответить на него `B!` — пересылка тоже должна сработать.
6. В ЛС отправить `/anon`, повторить шаги 2–4. В заголовке должен отображаться «анонима», без `@username`; исходное сообщение передаётся методом `copyMessage` без плашки «Переслано от». После теста вернуть `/deanon` по необходимости.
7. Отдельно ответить на сообщение бота в ЛС **без** `B!`: обычная reply-цепочка должна продолжать работать.
8. При попытке переслать в главную коммуну (или в коммуну с перенаправлением в главную) доставки быть не должно; бот объясняет запрет.

Внимание: `/anon` скрывает метку отправителя и Telegram-плашку первоначальной пересылки, но **не удаляет** имя/ссылки, явно написанные внутри текста либо изображения, и не анонимизирует сам файл. Защищённые (`has_protected_content`) сообщения Telegram пересылать нельзя. Некоторые служебные типы Telegram также нельзя копировать или пересылать.

## Логирование/ошибки

При входе `B!` через reply появляется `Forward command received chat=... message=... source=...`.

- Лога нет: бот не получил сообщение или его не обработал (например, устаревшая версия, не тот способ отправки). В **ЛС настройка Privacy Mode не требуется**.
- Лог есть, но нет доставки: проверить точное название коммуны, ограничения доступа и логи `Outbound forward failed` / `Outbound copy failed`.
- Если заголовок уже отправлен, но пересылка/копирование не удались, может появиться «Доставлено частично». Автоматически повторять не стоит: это может создать дубликат, нужно проверить целевой чат.

## Установка и откат

1. Остановить бота и сделать резервную копию папки, `.env` и MongoDB.
2. Распаковать Stage 5 ZIP поверх Stage 4 с заменой файлов. **Не затирать `.env` и не удалять MongoDB**.
3. Установить зависимости при необходимости, проверить тесты, затем запустить бот штатно.
4. Для отката остановить бота и распаковать предыдущий `Lackey_stage4_20261020.zip`. Изменений в схеме MongoDB нет.
